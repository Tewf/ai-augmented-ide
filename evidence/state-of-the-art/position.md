# Position: beside all, with one extension as the agent it drives

Step 4 of the review. Terms are in [frame](frame.md).

## Answer first

Build beside all. The two parts no extension has, the tree of topics and the verdict in place, are native editor interfaces that need no agent extension to exist. The other three parts reach the model through one open extension, named in [baseline](baseline.md).

## Why beside, not on

| Reason | Evidence |
|---|---|
| The missing parts do not live in an agent extension. The editor offers a tree view and a diagnostics list to any extension | no tree view call in the three extensions read; VS Code 2026 |
| The three read keep their interface in one webview that another extension cannot extend | review, features 1 and 2 |
| Cline 2026 shows no plugin interface in its source | review |
| The base can fall away: two of five open extensions are archived | sources |
| Fewer lines are tied to one project's internal changes | judgment, not measured |

## Why not wholly alone

| Reason | Evidence |
|---|---|
| Questions with options and memory as files already exist in an open extension | Kilo 2026 |
| Rules files already carry standing instructions in the three | Cline 2026; Continue 2026 |
| A protocol for editor to agent links exists and may carry a later version | ACP 2026 |

## What this position builds

Only what the review found missing, once the design of the method is approved:

1. A tree of topics, as a native tree view.
2. Verdicts of the machine's checks, as native diagnostics and a tree badge.
3. A list of the person's questions, kept apart from the model's output.
4. Delivery of the brief, the memory and the standing instructions to the chosen agent extension, as files it already reads.

Nothing here is built yet.

## Conditions

The position changes if the baseline stops being open or alive, if its memory cannot be edited by the person, or if the design of the method asks for something the files cannot carry.
